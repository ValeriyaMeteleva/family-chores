# Наши дела — первый черновик

Адаптивный прототип семейного приложения с PWA-оболочкой. Для проверки интерфейса откройте `index.html` в современном браузере или запустите локальный HTTPS/HTTP-сервер. Для установки на устройство приложение нужно разместить по HTTPS; открытие файла напрямую (`file://`) не поддерживает установку PWA.

После HTTPS-размещения его можно добавить на главный экран/рабочий стол из меню браузера. Интерфейс рассчитан на компьютеры и планшеты; отдельная сборка для Windows, Android или iPadOS не требуется.

## Что можно проверить

- выбор роли и ввод имени при первом запуске;
- создание двух родительских и двух детских профилей;
- добавление дел с ценой;
- повторная отправка одного дела в течение дня;
- комментарии ребёнка к заявке;
- PIN-подтверждение действий родителя;
- подтверждение или отклонение заявок и отображение баланса;
- отдельная сворачиваемая история подтверждённых дел;
- запрос частичной выплаты ребёнком и её подтверждение родителем по PIN;
- обязательное подтверждение получения выплаты ребёнком и история выплат.
- настройки цветовой темы на каждом устройстве;
- цели накоплений и погашение долга с автоматическим распределением вознаграждений;
- запрос ребёнком выплаты из накоплений, подтверждение оплаты родителем и получения ребёнком;
- настройка видимости нового дела для всех детей или выбранного ребёнка;
- редактирование и удаление дел родителем по PIN; уже отправленные заявки и история при удалении сохраняются.

## Публикация через GitHub Pages

В репозитории есть workflow `.github/workflows/pages.yml`: после публикации кода в ветку `main` он автоматически разместит сайт на GitHub Pages по HTTPS.

1. Создайте на GitHub **публичный пустой репозиторий** (например, `family-chores`). Не добавляйте при создании README, лицензию или `.gitignore`.
2. Откройте PowerShell в папке проекта `E:\YOUTube\Plagin\FamilyChores` и выполните команды, подставив имя своего аккаунта:

   ```powershell
   git remote add origin https://github.com/ВАШ_ЛОГИН/family-chores.git
   git add .
   git commit -m "Prepare family chores PWA for GitHub Pages"
   git push -u origin main
   ```

3. На GitHub откройте **Settings → Pages** и в разделе **Build and deployment** выберите **GitHub Actions**.
4. Откройте вкладку **Actions**, дождитесь успешного завершения workflow `Deploy Family Chores to GitHub Pages`. Адрес сайта появится в **Settings → Pages** и в результате workflow.
5. Откройте HTTPS-ссылку на каждом устройстве. В браузере выберите «Установить приложение» или «Добавить на главный экран».

Перед первым `git commit` проверьте адрес автора коммитов: если хотите скрыть личную почту, включите в **GitHub → Settings → Emails** параметр приватности и используйте выданный GitHub адрес `noreply`.

## Подключение Google-таблицы

Серверный код находится в папке `apps-script`, а прокси для безопасного браузерного подключения — в `cloudflare-worker`. Приложение отправляет запросы прокси, который вызывает Apps Script; адрес `/exec` хранится в секрете Cloudflare и не публикуется в клиентском коде. Вкладки таблицы — «Участники», «Дела», «Заявки», «Выплаты», «Финансы», «Запросы накоплений» и вспомогательная «Коды детей». При первом запросе обновлённый сервер создаёт новые вкладки и добавляет поле видимости в существующий лист «Дела». PIN и семейный код хранятся в свойствах скрипта в виде хешей; коды приглашения детей хранятся в таблице в виде хешей.

Цветовая тема сохраняется отдельно на каждом устройстве. После подтверждения выполненного дела сервер распределяет вознаграждение: сначала удерживает заданный процент на погашение долга (не более 50%), затем направляет заданный процент от остатка в накопления. При активном долге доля накоплений ограничена 20%; без долга — 50%. Долг не входит в доступный баланс ребёнка и может быть изменён или отменён только родителем после ввода PIN. Запрос на снятие накоплений тоже требует родительского решения, оплаты и подтверждения получения ребёнком.

1. Откройте закрытую Google-таблицу семьи.
2. Выберите **Расширения → Apps Script**. Замените содержимое `Code.gs` файлом `apps-script/Code.gs`. Файл `Bridge.html` можно оставить: новая версия приложения больше не использует его для связи.
3. Сохраните проект и перезагрузите страницу таблицы. В новом меню **Наши дела** выберите **Настроить сервер приложения**. Разрешите скрипту доступ к этой таблице. Введите новый четырёхзначный семейный PIN; сохраните показанный семейный код в личном месте. Повторный запуск настройки не сбрасывает код или PIN.
4. Нажмите **Развернуть → Управление развертываниями** и отредактируйте веб-развертывание, выбрав **Новую версию**. Если развёртывания ещё нет: **Новое развертывание → Веб-приложение**, **Выполнять от имени: я**, **У кого есть доступ: все**. Скопируйте URL `/exec` для настройки прокси.
5. Создайте Cloudflare Worker из `cloudflare-worker/worker.js` (Cloudflare Dashboard → **Workers & Pages** → **Create** → **Worker**). В настройках Worker добавьте секрет `APPS_SCRIPT_URL` со значением `/exec`-адреса Apps Script. Не вставляйте его в исходный код или GitHub. Опубликуйте Worker; его адрес будет иметь вид `https://family-chores-proxy.<аккаунт>.workers.dev`. Файл `cloudflare-worker/wrangler.toml` также можно использовать с Wrangler: `npx wrangler deploy --config cloudflare-worker/wrangler.toml`, затем `npx wrangler secret put APPS_SCRIPT_URL --config cloudflare-worker/wrangler.toml`. При открытии корневого адреса Worker в браузере он показывает, запущен ли Worker и задан ли секрет; это не заменяет тестовый вход через приложение.
6. Откройте опубликованное GitHub Pages приложение, выберите роль **Родитель** и введите адрес Worker, семейный код, имя и PIN. Адрес Worker сохранится на этом устройстве; первый родитель регистрируется при первом входе. На новых устройствах адрес Worker вводится один раз родителем.
7. В панели родителя нажмите **Добавить участника**, создайте детский профиль и передайте ребёнку показанный одноразово личный код входа вместе с семейным кодом. Для детского профиля используйте тот же адрес Worker; дети не вводят PIN родителя.

Worker разрешает запросы только с опубликованного GitHub Pages сайта и локальных адресов разработки. Проверка источника браузера не заменяет вход: все операции по-прежнему проверяют семейный код, роль и PIN на Apps Script. После обновления `Code.gs` опубликуйте новую версию веб-развертывания Apps Script. Новые вкладки и поле видимости существующих дел добавятся автоматически при первом запросе.

В веб-приложении Apps Script разрешён анонимный доступ, потому что выбран вход по семейному коду/PIN, а не проверка Google-аккаунта. Все операции с таблицей выполняются от имени владельца скрипта; сервер проверяет семейный код, роль и PIN для родительских изменений. Не публикуйте семейный код и коды детских профилей. PIN ограничивает попытки входа; поскольку он четырёхзначный, он подходит как семейная защита от случайного доступа, но не как пароль для особо чувствительных данных. После пяти неверных попыток PIN блокируется на 15 минут. Не выдавайте детям прямой доступ к Google-таблице и не включайте доступ «всем по ссылке». Открытое приложение обновляет данные с сервера примерно раз в 15 секунд; синхронизация учитывает версию данных и просит повторить операцию, если другой участник изменил таблицу раньше.

## Важно

До выполнения настройки и развёртывания Apps Script приложение продолжает работать как локальный прототип: данные хранятся в `localStorage` конкретного браузера. После подключения облака код профиля родителя не хранится на диске браузера; для входа снова потребуется PIN. Ребёнок входит по личному коду, который родитель получает при создании его профиля. Код нужен для выбора конкретного профиля и защиты от входа по одному только имени; храните его в семье и не публикуйте.

GitHub Pages публикует код приложения и Apps Script, но не семейные данные. Не добавляйте PIN, семейный код, коды приглашения или содержимое таблицы в GitHub. Уведомления между устройствами пока не реализованы.
